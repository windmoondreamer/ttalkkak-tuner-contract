# 딸깍 감도 조절기

`딸깍 감도 조절기.app`을 더블클릭해 실행한다.

## 상단 메뉴 — 부위별로 나뉘어 있다

| 메뉴 | 하는 일 |
|---|---|
| **하부 짐벌** | 홀센서(`GP26`·`GP27`) 실시간 확인 + 데드존·포화점·WASD 시작점 |
| **엄지 조이스틱** | 스틱(`GP28`·`GP29`) 실시간 확인 + 데드존·포화점·커서 속도 |
| **엄지쪽 버튼** | `M1` `M2` `SP` `MD` 눌림 확인 + 키 배치 |
| **검지·중지 버튼** | `F1`~`F8` `U1`~`U4` 눌림 확인 + 키 배치 |
| **프로필 페이지** | 페이지 개수·이름·전체 키 배치 |

각 부위 화면에서 **눌림 확인과 키 배치를 같은 자리에서** 한다. 어느 버튼인지 눌러서 확인하고 바로 그 버튼의 키를 고르면 된다.

### 조작성

보조기기 설정 도구라 미세 조작을 요구하지 않도록 만들었다.

- 상단 메뉴·버튼 타일·페이지 선택은 전부 **큰 버튼**이다. 목록을 펼쳐 고르는 드롭다운을 쓰지 않는다
- 슬라이더마다 **`−` `+` 버튼**이 붙어 있어 끌지 않고 한 칸씩 바꿀 수 있다
- 현재 값은 슬라이더 오른쪽에 **크게** 표시된다
- 페이지는 목록에서 `+` `−` 로 직접 추가·삭제한다

맨 아래 **전체 초기화**는 감도·커서 속도·키 배치·페이지 이름·페이지 개수를 전부 처음 상태로 되돌린다(확인 창이 뜬다).

## 프로필 페이지 — 최대 9개

`MODE` 링을 짧게 누르면 정한 개수만큼 순환한다. **기본은 처음 저장한 4개**다.

| 슬롯 | 기본 이름 | 기본 배치 |
|---|---|---|
| 1~4 | `FPS` `MOBA` `DESK` `MEDIA` | 원래 배치 그대로 |
| 5~9 | `사용자1`~`사용자5` | `DESK` 배치 복사 |

**프로필 페이지** 화면에 페이지가 목록으로 나온다. 아래쪽 **`+ 페이지 추가`** 를 누르면 다음 페이지가 붙고,
마지막 페이지 오른쪽의 **`−`** 로 뺀다. 추가 버튼에 몇 번 무슨 이름이 붙는지 미리 적혀 있다.

- 뺄 수 있는 건 **마지막 페이지뿐**이다. 중간을 빼면 뒤 번호가 전부 밀려서 잡아 둔 키 배치가 어긋난다
- 뺀 페이지의 키 배치는 **남아 있다.** 다시 추가하면 그대로 살아난다
- 4페이지가 아니면 `4페이지로 되돌리기` 가 같이 뜬다
- 이름은 자유롭게 바꿀 수 있고 펌웨어까지 그 이름이 넘어간다

키 배치는 페이지마다 따로 저장되며, `이 페이지 기본 배치 복원`과 `DESK 배치 복사해오기`로 빠르게 되돌릴 수 있다.
편집할 페이지는 목록의 `이 페이지 편집` 으로 고르고, 키 배치 상자에 **`편집 중 <이름>`** 으로 표시된다.

> `SP`(스틱 클릭)와 `MD`(MODE 링)는 모드 전환·재캘리브레이션·레벨업 기능이 걸려 있어 앱에서 바꾸지 않는다. 감도와 FPS·MOBA·DESK 각 프로필의 키 배치를 조절한 뒤, 저장할 때 `ttalkkak` 폴더를 선택한다.

`02_설계/툴/firmware/ttalkkak/sensitivity_override.h`

앱은 키 배치 파일도 함께 생성한다.

`02_설계/툴/firmware/ttalkkak/mapping_override.h`

그 다음 펌웨어 폴더에서 실제 기기에 다시 올린다.

```sh
./build.sh diagpcf upload  # 현재 PCF8575 배선일 때
# 또는
./build.sh dev upload      # GPIO 직결 배선일 때
```

나머지 14개 물리 버튼은 페이지마다 키, 마우스 클릭/연사, Shift·Ctrl 토글, 브라우저·탭 동작으로 바꿀 수 있다.
생성되는 `mapping_override.h`에는 9슬롯 전부와 `TTK_PROFILE_COUNT`(순환할 개수)가 들어간다.

## 멀티미디어 · Nintendo Switch 모드

짧은 MODE 링 누름으로 `FPS → MOBA → DESK → MEDIA`를 순환한다. `MEDIA`는 하부 짐벌로 커서를, 엄지 스틱으로 스크롤을 움직이며 YouTube의 `J`(10초 뒤로), `K`(재생/정지), `L`(10초 앞으로), `F`(전체화면), `/`(검색창) 단축키를 기본 배치한다.

MODE 링을 **2.5초 이상** 누른 뒤 떼면 USB 정체성이 PC 키보드·마우스와 **Nintendo Switch 게임패드** 사이에서 전환된다. Switch 모드에서는 키 배치 파일을 쓰지 않고, 하부 짐벌=왼쪽 스틱·엄지 스틱=오른쪽 스틱·물리 버튼=Switch 버튼/D패드로 동작한다.

기본 FPS 배치의 Shift(F5)와 Ctrl(F7)는 **누르는 동안만** 유지되고 손을 떼면 즉시 해제된다. 앱에서 `토글`을 고르면 해당 동작은 다음에 같은 버튼을 누를 때까지 유지되는 것이 정상이다.

## 실시간 입력 테스트

앱의 **실시간 입력 테스트**에서 `/dev/cu.usbmodem*` 또는 `/dev/cu.usbserial*` 포트를 골라 연결하면, 실제로 눌린 F1~F8·M1·M2·U1~U4·SP·MD 버튼이 초록색으로 표시된다.

이 기능은 펌웨어의 `btnev=XXXX` 진단 출력을 사용한다. 현재 PCF8575 배선은 먼저 아래 명령으로 진단 펌웨어를 올린다.

```sh
cd '02_설계/툴/firmware'
./build.sh diagpcf upload
```

GPIO 직결 배선은 `./build.sh diag upload`를 쓴다. 테스트가 끝나면 평소에 쓸 빌드로 다시 업로드한다.

## 하부 짐벌 · 엄지 스틱 테스트

**실시간 입력 테스트** 안에 축 패드 두 개가 있다. 왼쪽이 **하부 짐벌**(홀센서, `GP26`·`GP27`),
오른쪽이 **엄지 스틱**(`GP28`·`GP29`)이다. 버튼 테스트와 같은 연결을 쓰므로 포트를 한 번만 연결하면 된다.

```sh
cd '02_설계/툴/firmware'
./build.sh diagpcf upload      # PCF8575 배선 (현재 실물)
./build.sh diag upload         # GPIO 직결 배선
```

펌웨어가 약 50Hz로 `axev=` 줄을 보내고 앱이 그걸 그린다(`AXIS_EVENT_MS`, 기본 20ms).

### 패드 읽는 법

| 표시 | 뜻 |
|---|---|
| **주황 점선 원** | 데드존. 점이 이 안에 있으면 출력은 0이다 |
| **초록 점선 원** | 포화점. 여기 닿으면 최대 출력 |
| **파란 점** | 현재 위치 |
| `출력` | 실제로 게임·커서에 나가는 값 (−1.00 ~ +1.00) |
| `ADC` | EMA만 거친 날값. **센서가 물리적으로 움직이는지**는 이걸로 본다 |
| `중립에서` | 부팅 때 잡은 중립 대비 변화량 |
| `최대 도달` | 이번 세션에서 도달한 최대치 (짐벌만) |

### 판정

짐벌을 **8방향으로 끝까지** 밀고 `최대 도달`을 본다. 앱이 오른쪽에 한 줄로 판정도 내준다.

| 관측 | 조치 |
|---|---|
| 양축 `최대 도달` ≥ 0.85 | 정상 |
| `미연결` 배지 | 홀센서가 `GP26`·`GP27`에 물렸는지, 3.3V가 오는지 확인 |
| `ADC`는 움직이는데 `출력`이 0 | 데드존이 너무 크다 — 낮춘다 |
| `최대 도달`이 0.5 미만인 축 | 그 축 배선·자석 위치 확인, 또는 포화점을 낮춘다 |
| 양축 0.5~0.85 | 포화점을 낮추면 끝까지 나간다 |
| 손 뗐는데 점이 중앙에 안 옴 | `MODE` 링 1초 홀드로 재캘리브레이션 |

> 중립값은 부품마다 다르므로 부팅할 때마다 자동 캘리브레이션한다. **캘리브레이션 중에는 손을 떼고 있어야 한다.**
> 미연결 축은 값이 마구 흔들려서 커서가 날뛰므로 펌웨어가 자동으로 끈다 — 그때 `미연결` 배지가 뜬다.

감도·키 배치 저장은 다음 펌웨어 빌드 때 반영된다. 실행 앱을 다시 만들려면 `./build_app.sh`를 실행한다.
